The Famulus universe

Layers, components and machines from import folder to landing page

Published

October 14, 2026

What Famulus is as a whole, and the order of its properties, is set out in the canonical account. This page lists every layer between a source folder and a published landing page, with the component, path, port and role of each layer. Concepts are on Famulus reference. Storage and operation are on DuckLake.

Layer map

Components

Layer Component Path Port Role
Sources import folder scholarly/research/<project>/import/ (+ MANIFEST.yaml) — PDFs, images, metadata files, databases as delivered; never modified
Intake skill pdai-collection-intake pdai/skills/pipeline/pdai-collection-intake/ — eight stages: inventory, profile, DTD draft, segment plan, review gate, build, famulus DB, lake export. See Skills
Collection PDAI collection /Volumes/PDAI-1/pdai-collections/<coll>/ — page XML, page images, biblio.xml, per-document index.duckdb, legacy sidecars (*_fql, *_stanza, …). See PDAI Collections, Document Structure
Collection code DTD, segment plan pdai/collections/<coll>/config/ — famulus.yaml, page.dtd, segments.yaml. See XML Schemas
Famulus DB <coll>_famulus.duckdb /Volumes/PDAI-1/pdai-collections/<coll>/ — complete famulus reference data of one collection, schema famulus-reference/1; rebuildable
DuckLake catalog + Parquet catalog pdai-collections/_lake/famulus.ducklake, Parquet <coll>/_lake/, core _lake/core/ — authoritative store of all collections; snapshots, releases. See DuckLake
Read replica famulus.read.ducklake next to the catalog — copy published after every write session; all readers attach it
Query trace famulus_reference_traces.duckdb pdai-collections/_lake/ — fr_run, fr_run_step; written only by the MCP server
API famulus-reference MCP server pdai/famulus-reference/ 5135 fr_* tools (streamable HTTP /mcp), harvest routes /oai, /jsonld/<coll>, /iiif/<coll>/<doc>/manifest.json, /peers. See MCP Servers
Proxy ai-platform-mcp platform/mcp-server/ stdio lists and proxies the fr_* tools. See MCP Orchestra
Proof famulus-proof development/famulus-proof/ — evidence, proofs; lake mode FAMULUS_LAKE=1; fr: resolver (famulus_proof/lake.py) for Clause.address; probe lab (scripts/satz_labor.py: normalise, filter, classify), described in the paper The Famulus Probe Lab
Notebook famulus-notebook development/famulus-notebook/ 5118 notebooks; guard resolves fr: citations. See Famulus Notebook
Lektorat ai-lektorat publication/ai-lektorat/ — text review; uses famulus-proof evidence
Orchestration ai-agent-orchestrator Partituren in skill folders (partitur.yaml) — executes Partituren, e.g. pdai-collection-intake (goal path pipeline/intake/collection)
Query ai-query pdai/agents/ai-query/ 5113 query resolution; lake adapter planned
Landings landings2026 scholarly/projects/landings2026/ — static landing pages; reading through the lake planned. See Landing backends

Machine topology

Machine Tree Role
mac-studio ~/ai-mac-studio central machine: PDAI-1 drive with all PDAI data, DuckLake (single writer), famulus-reference MCP server, all Famulus development, syncthink runner
client (e.g. openscience) ~/ai-openscience (Syncthing mirror of ~/ai-mac-studio) code edits; PDAI-1 mounted via SMB (read); studio-only steps queued in ~/syncthink/queue/ (allow-list platform/config/syncthink_jobs.yaml) or run by the owner on mac-studio

Steps marked [STUDIO] (lake export, migration, maintenance, the PDAI-1 space audit platform/scripts/pdai1_space_audit.py) run only on mac-studio. On every other host a write to the production catalog raises WriteRefused.

NoteStatus on 2026-10-23

The famulus-reference MCP server runs on the Mac Studio (launchd com.ai-platform.famulus-reference-mcp, /health 200 on port 5135). The DuckLake holds eight collections (platform paper, 20 October 2026). Since 20 October 2026 each migrated collection carries one corpus file with a BM25 index and one famulus file; the vector store is removed (data layer paper). The directory of peer nodes is in place and empty.
