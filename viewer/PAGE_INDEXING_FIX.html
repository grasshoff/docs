Page Indexing Fix - 1-Based vs 0-Based

Problem

The viewer was displaying content from the next page instead of the current page. When navigating to page 6, it showed content from page 7.

Root Cause

Mismatch between page numbering and file indexing:

  • Viewer UI: Uses 1-based page numbers (Page 1, Page 2, …, Page 217)
  • File system: Uses 0-based indices (page_000.png, page_001.png, …, page_216.png)

Before the fix:

// Page 6 in UI
const paddedNum = String(6).padStart(3, '0');  // "006"
const imagePath = `page_006.png`;  // ❌ This is the 7th image (index 6)!

Result: Page 6 loaded page_006.png (7th image) instead of page_005.png (6th image).

Solution

Convert from 1-based page number to 0-based file index before loading files:

// Convert 1-based page number to 0-based file index
const fileIndex = pageNum - 1;  // Page 6 → index 5
const paddedNum = String(fileIndex).padStart(3, '0');  // "005"
const imagePath = `page_${paddedNum}.png`;  // ✅ page_005.png (6th image)

}

Impact on Other Documents

This fix applies to all documents in the viewer. Any document using the standard PDAI page-centric structure will now load pages correctly.

Related Issues

Issue 1: PIDX Mismatch in XML

If XML files have incorrect pidx attributes (e.g., page_000.xml with pidx="1"), use the fix_pidx tool:

python src/ai_scholar/fix_pidx.py ../pdai/DocumentName/xml

Issue 2: File Naming Convention

All files must follow the standard naming convention: - Images: page_000.png, page_001.png, …, page_216.png - XML: page_000.xml, page_001.xml, …, page_216.xml - HTML: page_000.html, page_001.html, …, page_216.html

See docs/NAMING_STANDARDS.md for complete specification.

Why This Bug Occurred

  1. Natural Assumption: UI page numbers are typically 1-based (human-friendly)
  2. File System Convention: File indices are 0-based (computer-friendly)
  3. Missing Conversion: Code didn’t convert between the two systems
  4. Off-by-One Error: Classic programming mistake when mixing counting systems

Prevention

To prevent similar issues in the future:

  1. Always comment whether variables are 0-based or 1-based
  2. Convert explicitly at boundaries between systems
  3. Test edge cases: Page 1, middle page, last page
  4. Use descriptive names: pageNum (1-based) vs fileIndex (0-based)

Technical Details

JavaScript String Padding

String(0).padStart(3, '0')   // "000"
String(5).padStart(3, '0')   // "005"
String(99).padStart(3, '0')  // "099"
String(216).padStart(3, '0') // "216"

Index Conversion

// 1-based to 0-based
const fileIndex = pageNum - 1;

// 0-based to 1-based
const pageNum = fileIndex + 1;
