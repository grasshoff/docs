Viewer Architecture

Static HTML viewer design and data flow

Overview

AI-Viewer is a static HTML/JavaScript application that runs in any web browser. It serves PDAI documents through a simple HTTP server, with no backend framework required.

System Architecture

Core Components

Static HTTP Server

The viewer works with any HTTP server. Python’s built-in server is recommended:

# Start from project root
cd /path/to/2026project
python -m http.server 4100

Key requirements:

  • Serves static files from project root

  • No special configuration needed

  • Works with nginx, Apache, or any HTTP server

Viewer Application (viewer.html)

Single-page application with all logic embedded:

<!DOCTYPE html>
<html>
<head>
    <title>AI Scholar</title>
    <script src="https://cdn.jsdelivr.net/npm/mathjax@3/..."></script>
    <style>/* All styles inline */</style>
</head>
<body>
    <nav><!-- Navigation bar --></nav>
    <main><!-- Content panels --></main>
    <script>
        class DocumentViewer {
            // All viewer logic
        }
    </script>
</body>
</html>

Key features:

  • Self-contained HTML file

  • No build process required

  • MathJax loaded from CDN

  • All styles and scripts inline

Document Discovery

The viewer discovers documents through multiple sources:

  1. Primary: pdai/index.json — Canonical document list
  2. Fallback: pdai-documents.json — Cached copy at project root
  3. Last resort: Hardcoded list of known documents

Page-Centric Structure

All path resolution uses the page-centric structure:

pdai/DocumentName/
└── pages/
    └── page_NNN/
        ├── page_NNN.png           # Image
        ├── page_NNN.xml           # OCR XML
        ├── page_NNN.html          # HTML conversion
        ├── page_NNN_translation_english.xml  # Agent output
        └── page_NNN_fig_1.png     # Extracted figure

Path Helper Functions

class DocumentViewer {
    getPagePath(pageIdx, ext) {
        const p = String(pageIdx).padStart(3, '0');
        return `${this.apiBase}/pages/page_${p}/page_${p}.${ext}`;
    }

    getAgentPath(pageIdx, agentName) {
        const p = String(pageIdx).padStart(3, '0');
        const agent = agentName.replace(/-/g, '_');
        return `${this.apiBase}/pages/page_${p}/page_${p}_${agent}.xml`;
    }

    getFigurePath(pageIdx, figNum) {
        const p = String(pageIdx).padStart(3, '0');
        return `${this.apiBase}/pages/page_${p}/page_${p}_fig_${figNum}.png`;
    }
}

Performance Considerations

Browser Caching

Static files are cached by the browser:

Content Type Cache Strategy
Page images Long cache (immutable)
HTML/XML content Cache with revalidation
Viewer assets Long cache

Lazy Loading

Content is loaded on demand:

async loadPage(pageIdx) {
    // Load image
    const img = new Image();
    img.src = this.getPagePath(pageIdx, 'png');
    
    // Load text
    const response = await fetch(this.getPagePath(pageIdx, 'html'));
    const html = await response.text();
    
    // Render
    this.displayImage(img);
    this.displayText(html);
}

Page Count Detection

Binary search for efficient page count detection:

async detectPageCount() {
    let low = 0, high = 1000;
    
    while (low < high) {
        const mid = Math.floor((low + high + 1) / 2);
        const path = this.getPagePath(mid, 'png');
        
        try {
            const res = await fetch(path, { method: 'HEAD' });
            if (res.ok) {
                low = mid;
            } else {
                high = mid - 1;
            }
        } catch {
            high = mid - 1;
        }
    }
    
    return low + 1; // Convert 0-indexed to count
}

### Page Load Sequence

```{mermaid}
%%| fig-cap: "Page load sequence"
sequenceDiagram
```
